# Platform headers the NDK does not have

The plugin is built with the NDK, but the code it is made of (generated AIDL
code, libfmq, AOSP's effect base classes) was written against platform
headers. What is here fills that gap. Nothing here is linked against a
platform library the NDK does not offer: the plugin's only runtime
dependencies are libbinder_ndk, liblog, libc, libm and libdl.

**Vendored unmodified from AOSP (Apache-2.0):**

- `android/binder_*.h`, `android/persistable_bundle*.h`: the current
  `libbinder_ndk` header set. Code generated by build-tools 37 uses
  declarations newer than NDK r27's copy. The symbols themselves exist in
  every `libbinder_ndk.so` from Android 14 on, and `check-elf.sh` fails the
  build if the plugin ever needs one newer than that.
- `cutils/native_handle.h`: the type libfmq's descriptor shim uses.
- `android-base/thread_annotations.h` (system/libbase, android-17.0.0_r1):
  clang thread safety macros used by AOSP's effect base.

**Written for this project, standing in for platform headers:**

- `Utils.h`: the two helpers from libaudioaidlcommon that EffectContext
  uses to size its queues (`getChannelCount`, `getFrameSizeInBytes`).
- `system/audio_effects/aidl_effects_utils.h`: only the protocol constants
  (event flag bits, the versions that added reopen and draining).
- `system/thread_defs.h`: the two audio thread priorities.
- `utils/Trace.h`: systrace markers, compiled to nothing.
